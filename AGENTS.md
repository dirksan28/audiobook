# AGENTS.md

## Purpose

This project generates German audiobook MP3s from one or more input directories or explicitly selected text files. Each `.txt` file becomes an `.mp3` with the same stem in the same directory. Speech is generated by one of three Thorsten-Voice engines — CosyVoice3, Kokoro, or Piper — and converted from WAV to MP3 with ffmpeg.

## Layout

Project files live in the repository root.

- `tts_audiobook.py`: the executable generator, standard-library-only Python.
- `README.md`: user-facing usage and troubleshooting documentation.
- `AGENTS.md`: project conventions for agents.

## Environment

- Target Python: 3.9 or newer.
- Do not add third-party Python dependencies to the script. Use the standard library.
- ffmpeg with `libmp3lame` is required at runtime.
- CosyVoice and Kokoro use Docker by default. An already running server can be used with `--docker never`.
- Piper is a local subprocess and does not use Docker or the network.
- Linux is the primary target. macOS must work with CPU-only Docker Desktop and native Kokoro/Piper.
- Never assume a GPU is present, and do not treat GPU detection as a VRAM check. CosyVoice3 needs more than 2 GB of VRAM; on a 2 GB GPU use `--gpu off`. CosyVoice GPU acceleration is Linux-only and requires a working `nvidia-smi` plus either the Docker `nvidia` runtime or an NVIDIA CDI specification.
- Kokoro and Piper are CPU-only in this project. `--gpu on` must fail for them.

## Common Commands

Compile-check the script:

```bash
python3 -m py_compile tts_audiobook.py
```

Show all CLI options:

```bash
./tts_audiobook.py --help
```

Preview the planned file operations without Docker or network access:

```bash
./tts_audiobook.py --text-dir path/to/texts --dry-run
./tts_audiobook.py --text-file path/to/chapter.txt --dry-run
./tts_audiobook.py --text-file path/to/chapter-01.txt path/to/chapter-02.txt --dry-run
./tts_audiobook.py --engine kokoro --text-dir path/to/texts --dry-run
./tts_audiobook.py --engine piper --piper-model models/de_DE-thorsten-high.onnx --text-dir path/to/texts --dry-run
```

Normal CosyVoice generation:

```bash
./tts_audiobook.py --text-dir path/to/texts
```

Kokoro generation:

```bash
./tts_audiobook.py --engine kokoro --text-dir path/to/texts
```

Piper generation:

```bash
./tts_audiobook.py --engine piper --piper-model models/de_DE-thorsten-high.onnx --text-dir path/to/texts
```

Force regeneration:

```bash
./tts_audiobook.py --text-dir path/to/texts --force
```

Require GPU usage for CosyVoice:

```bash
./tts_audiobook.py --text-dir path/to/texts --gpu on
```

Test against a mock TTS server:

- CosyVoice: answer `GET /health` with `{"status":"ok","model":"CosyVoice3-Thorsten"}` and `POST /tts` with a valid RIFF/WAVE file; inspect multipart fields.
- Kokoro: answer `GET /health` with `{"status":"ok","repo_id":"Thorsten-Voice/Kokoro","epoch":"5","device":"cpu"}` and `POST /tts` with JSON; verify the request body contains `text` and numeric `speed`.
- Run the script with `--server-url http://127.0.0.1:<port> --docker never`.
- Verify that MP3s are created next to the text files and that a second run skips existing files.
- Verify that `--force`/`--overwrite` regenerates existing files.
- Test retries by returning HTTP 500 for the first `/tts` request.

Test Piper without a real model by using a fake executable:

- The fake command must accept `--model`, `--output_file`, `--length_scale`, and optional `--speaker`.
- It must read text from stdin and write a valid WAV file to `--output_file`.
- Verify `--speed 0.5` produces `--length_scale 2`, and that `--piper-length-scale` overrides speed.
- Verify `--cooldown` prints the cooldown line and sleeps after each generated file; negative values are rejected.
- Verify `--spell-numbers auto` changes `C96` and `1887` to German words for CosyVoice and leaves Kokoro/Piper text unchanged.
- Verify `--spell-numbers off` sends digits unchanged and `--spell-numbers de` also applies to Kokoro/Piper.
- Verify that an already running managed container is reused, not restarted.
- Verify that normal exit, Ctrl+C, and SIGTERM stop the managed container, and that `--docker never` leaves an external server untouched.
- Run the number and lifecycle tests with `python3 -m unittest discover -s tests -v`.

## Behavior Contracts

- One or more input paths are required via `--text-dir` or `--text-file`; the two flags are aliases for the same option and may be repeated. Each path may be a directory or a text file. If the option is omitted, the script must print an error and exit without contacting Docker or the server.
- Inputs are processed in CLI order. Files found in a directory are naturally sorted. Duplicate resolved paths are removed while preserving the first occurrence.
- When every input is an explicit file, `--recursive` and a non-default `--glob` must be rejected. When at least one directory is supplied, these options apply to the directory inputs.
- Each directory input must contain at least one matching `.txt` file.
- Output path is always the source path with its suffix replaced by `.mp3`.
- Only `.txt` inputs are processed; an explicit file must end in `.txt`.
- Existing non-empty MP3s are skipped unless `--force` or its alias `--overwrite` is set.
- Before each pending chapter, print `index/total: source-name`.
- After each MP3 is atomically published, print the target name, playback duration, file size, and render duration.
- `--cooldown SECONDS` pauses after each generated MP3, including the last, and prints `Cooling down for N second(s)`. Skipped or failed files do not trigger a cooldown.
- The script sends one synthesis request per chapter. Do not split chapters into multiple requests unless explicitly requested; CosyVoice handles long text internally and chunk boundaries can hurt prosody.
- Engine defaults:
  - `cosyvoice`: image `thorstenvoice/cosyvoice-tts:cosyvoice3`, container `cosyvoice-tts`, volume `cosyvoice_models`.
  - `kokoro`: image `thorstenvoice/kokoro-tts:latest`, container `thorsten-kokoro-tts`, volume `kokoro_cache`.
  - `piper`: local CLI, no container.
- CosyVoice form fields: `text`, `speed`, `normalize_text`, `normalize_loudness`, `lufs_target`. The Thorsten-Voice image currently reads only `text` and `speed`; the normalization fields are for compatible external servers.
- `--spell-numbers` defaults to `auto`: German number words for CosyVoice, unchanged text for Kokoro and Piper. `de` enables German spelling for all engines; `off` disables it.
- German number spelling must turn `C96` into `C sechsundneunzig`, `1887` into `achtzehnhundertsiebenundachtzig`, `08/15` into `null acht fünfzehn`, and `7,63` into `sieben Komma sechs drei`. Patent numbers after `Nummer`/`Patentschrift` are read digit-by-digit.
- Apply German number spelling before the CosyVoice blank-line collapse and before the request body is built. Do not rely on the server for German number normalization.
- Kokoro JSON fields: `text`, `speed`. Its `--kokoro-epoch` maps to the container environment variable `KOKORO_EPOCH`. Reusing a container with a different epoch must fail and suggest `--recreate`.
- Piper arguments: `--model`, `--output_file`, `--length_scale`, and optional `--speaker`; text is passed through stdin. `--speed` maps to `length_scale = 1 / speed`; `--piper-length-scale` overrides it.
- The managed CosyVoice container publishes the configured port and sets `PORT` to the same value.
- The managed Kokoro container maps the configured host port to internal port `8000`.
- `--docker-network host` starts the managed container without `-p`; the server listens directly on host port `8000`, so `--port` must be `8000`. Reusing a container with a different network mode must fail and suggest `--recreate`.
- If a managed container is already running, reuse it and do not restart it. `--recreate` is the only explicit exception.
- Always stop the managed container on script exit: normal completion, unhandled errors, Ctrl+C, SIGTERM, and SIGHUP. This also applies to a container that was already running before the script started. `--stop-container` is accepted for compatibility but is not required.
- Do not stop an external server when `--docker never` is used.
- SIGKILL and power loss cannot be handled; the container may remain running in those cases.
- GPU selection is `auto` by default. `--gpu on` must fail loudly for CosyVoice if GPU acceleration is unavailable. `--gpu off` forces CPU for newly created CosyVoice containers; an existing GPU container is reused unless `--recreate` is set. Kokoro and Piper reject `--gpu on`.
- Do not silently fall back to CPU when the user explicitly requested `--gpu on`.

## Implementation Conventions

- Use `pathlib` for paths and pass subprocess arguments as lists, never as shell strings.
- Keep temporary WAVs outside the source directory and delete them automatically.
- Write MP3s to a temporary file in the destination directory, validate the result, then use `os.replace` for atomic publication.
- Preserve retries and actionable errors. Do not swallow failures silently.
- Keep CLI defaults aligned with the Thorsten-Voice API defaults where practical: speed `1.0`, text normalization off, loudness normalization off.
- Keep engine-specific validation centralized. Normalization flags belong to CosyVoice; Piper flags and `--piper-model` belong to Piper; Docker image/container/volume overrides belong to Docker engines.
- Do not document normalization fields as effective with the bundled Thorsten-Voice image; its `/tts` handler accepts only `text` and `speed`.
- Keep German number spelling client-side and independent of server support. When its WeText frontend is available, the bundled image reads German numbers as English; if WeText fails to load, the server may log `no frontend is avaliable`.
- Implement container cleanup with both a `finally` block and an `atexit` fallback, plus SIGTERM/SIGHUP handlers. Do not rely on `--stop-container` or on the container's `--restart unless-stopped` policy.
- Do not hardcode personal absolute paths in new features; use `--text-dir`/`--text-file` or paths relative to the script.
- Keep README and `--help` in sync when options change.
- Collapse blank lines to spaces in CosyVoice request text. The Thorsten-Voice image's WeText normalizer returns an empty result for `\n\n` combined with digits, which the server reports as an empty HTTP 500 error.

## Generated Files

Do not commit generated `.mp3` or temporary `.wav` files. The source of truth is the `.txt` content plus `tts_audiobook.py`.
